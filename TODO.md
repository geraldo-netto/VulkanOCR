# VulkanOCR review — 2026-08-21

| id | severity | effort | description |
| --- | --- | --- | --- |
| VOCR-0048 | medium | xs | **A pool with every worker retired crashes instead of falling back.** `read` falls back to the primary engine only on `len(self._names) == 1` (src/vulkanocr/parallel.py:212); after the last worker is retired (`_retire`, parallel.py:164) `_names` is empty, the check misses, and `_dispatch`'s `min(self._cost.values())` (parallel.py:233) raises `ValueError: min() iterable argument is empty` — an unnamed crash where the in-process primary could have answered the page. Confirmed by repro. Fix: `len(self._names) <= 1`. |
| VOCR-0049 | low | xs | **`ParallelOcr.close` is not safe to call twice.** The second call reaches `channel.put(None)` / `self._replies.close()` on queues the first call closed and raises `ValueError: Queue ... is closed` (src/vulkanocr/parallel.py:289,304) — against the contract its sibling `OcrEngine.close` states and keeps ("Safe to call twice", engine.py:197). Confirmed live. Guard with a closed flag or tolerate closed queues. |
| VOCR-0050 | medium | s | **On a one-GPU machine the pool pays for a worker it never uses.** `read` always takes the primary fallback when `len(self._names) == 1` (src/vulkanocr/parallel.py:212), yet `__init__` still spawns a worker process per device (parallel.py:109-118) — so every single-device `--all-gpus` run holds a second recognition engine's Vulkan allocations and a spawned process for nothing, forever. Skip the worker fleet entirely when `hardware_devices` returns one device. |
| VOCR-0052 | low | xs | **A recognition-only engine still demands the detection files exist.** `nets=("rec",)` (VOCR-0042) skips loading the det net, but `models.validated()` (called at engine.py:157) still requires `det_param` and its `.bin` on disk — a "half engine" whose contract validates the whole catalog entry. Validate only the halves that were asked for (the dictionary always). |
| VOCR-0053 | low | s | **`_read_and_report` holds three jobs.** src/vulkanocr/cli.py:87-134 owns the sampler thread's lifecycle, the timing loop, and all of the printing in one function; the sysfs busy-sampler (`gpu_busy_paths`/`sample_gpu_busy`, cli.py:24-36) is proof instrumentation, not CLI. Wrap the sampler as a context manager in its own module and let the report function only report — which also makes the sampler reusable and the printing testable. |
